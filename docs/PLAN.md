## 1. 목표

앨런 튜링과 고든 웰치먼이 설계한 암호 해독기 **봄베(Bombe)** 를 재현한다.

**최종 목표는 기계식 실물이다** (사용자 지시 2026-11-15). 전시관 등에 전시해 관람객이 직접 실습할 수 있어야 한다(전시 여부는 미확정이지만 설계 요구사항으로 둔다).

**전시 구성: 같은 봄베를 세 방식으로 — 기계식(기어 드럼) → 릴레이식 → FPGA(전자식).** 세 대를 나란히 두면 컴퓨터의 발전(기계 → 전기기계 → 전자)을 한눈에 보여 준다 (사용자 지시 2026-11-15: 셋 다 유지). 따라서 FPGA도 실물의 보조 장치일 뿐 아니라 **세 번째 전시물**이다. 같은 메뉴를 세 기계에 걸어 같은 정지가 나오는 것을 보여 주고, 속도 차이(위치당 시간)를 비교한다.

소프트웨어(Phase 1)는 세 기계 모두의 기준 모델·검증 도구이고, RTL 기준 모델은 FPGA와 릴레이식의 설계 기준이다. 전 과정은 LaTeX 보고서로 정리한다.

"재현"의 기준은 두 가지다.

1. **기능**: 에니그마 암호문과 크립(crib, 추정 평문)이 주어지면 로터 순서·로터 위치·플러그보드 배선 후보(stop)를 찾아내고, 이를 검증해 실제로 해독한다.
2. **구조**: 결과만 맞추는 무차별 탐색기가 아니라, 실제 기계의 구성요소(드럼, 메뉴 배선, 대각선 보드, 테스트 레지스터, 체킹 머신)를 1:1로 대응시켜 구현한다. 이 대응 관계가 이후 RTL·실물 단계의 설계도가 된다.

## 3. 재현 대상

### 에니그마 (봄베의 공격 대상이자 검증 도구)

| 기종 | 로터 | 반사판 | 로터 순서 수 |
|---|---|---|---|
| Enigma I (육·공군) | I–V 중 3개 | B, C | 60 |
| M3 (해군) | I–VIII 중 3개 | B, C | 336 |
| M4 (해군 U보트) | I–VIII 중 3개 + Beta/Gamma | 얇은 B, 얇은 C | 1,344 |

공통 요소: 링 설정(Ringstellung), 플러그보드(Stecker), 이중 스테핑(double stepping), 로터 VI–VIII의 노치 2개.

### 봄베

- **3로터 봄베 (영국, BTM 제작)**: 에니그마 등가 유닛 36개(12개 × 3뱅크), 유닛당 드럼 3개. 로터 순서 하나당 26³ = 17,576 위치를 탐색.
- **대각선 보드 (웰치먼)**: "A가 B와 연결되면 B도 A와 연결된다"는 플러그보드의 대칭성을 배선으로 강제해 거짓 정지를 크게 줄인 장치. 루프가 적은 메뉴도 쓸 수 있게 해 준 핵심 개선.
- **정지 판정**: 테스트 레지스터의 26선 중 일부만 통전되면 정지(모순 없는 가설이 남아 있음), 26선 전부 통전되면 통과.
- **체킹 머신**: 정지 위치에서 플러그보드 전체 배선과 링 설정을 유도하고 모순 여부를 확인하는 후처리 단계.
- **4로터 봄베**: 로터 순서 하나당 26⁴ = 456,976 위치. 미 해군 봄베(NCR 제작)를 기준 모델로 하고 영국식 4로터 변형은 자료 조사 후 포함 여부를 정한다.

## 4. 아키텍처

```
                     ┌──────────────────────────────┐
  사람(조작자) ───▶  │ python/christopher           │  고수준 조작 API · 노트북
                     └──────────────┬───────────────┘
                                    │ PyO3 (maturin)
                     ┌──────────────▼───────────────┐
                     │ crates/christopher-py        │  얇은 바인딩 계층
                     └──────────────┬───────────────┘
                     ┌──────────────▼───────────────┐
                     │ crates/christopher-core      │  순수 Rust, 외부 런타임 의존 없음
                     │  enigma · menu · bombe · check│
                     └──────┬────────────────┬──────┘
                            │                │
              data/vectors (검증 벡터)   (향후) WASM → web/
                            │
                     ┌──────▼───────┐      ┌───────────┐
                     │ rtl/         │ ───▶ │ hardware/ │
                     └──────────────┘      └───────────┘

  모든 단계의 결과·그림·출처 ───▶ report/ (LaTeX 최종 보고서)
```

설계 원칙:

- **코어는 바인딩과 분리한다.** `christopher-core`는 Python·WASM에 대해 아무것도 모른다. 같은 코어를 나중에 웹(WASM)과 RTL 검증용 기준 모델로 그대로 재사용하기 위함이다.
- **Rust 코어가 기준(golden) 모델이다.** RTL과 실물은 코어가 내보낸 검증 벡터(`data/vectors/`)와 결과가 일치해야 한다.
- **배선표는 코드가 아닌 데이터로 둔다.** 로터·반사판·드럼 배선은 `data/wirings/`에 두고 Rust, RTL이 같은 원본을 읽는다.

### 코어 모듈 구성 (`christopher-core`)

| 모듈 | 역할 |
|---|---|
| `enigma` | 로터, 반사판, 플러그보드, 스테핑. Enigma I / M3 / M4 |
| `menu` | 암호문에 크립을 정렬(같은 글자로 암호화되지 않는 성질 이용), 글자 연결 그래프 생성, 루프 분석, 봄베 유닛 수 제약 안에서 메뉴 선택 |
| `bombe` | 스크램블러(드럼 3·4개), 26선 케이블, 대각선 보드, 테스트 레지스터, 드럼 구동과 정지 판정 |
| `check` | 체킹 머신: 정지 → 플러그보드 전체 유도 → 링 설정 → 해독 확인 |

봄베 내부 상태는 26개 케이블 × 26선 = 676개 노드의 통전 여부이며, 이를 `[u32; 26]` 비트마스크로 표현하고 고정점까지 전파한다. 이 표현은 RTL의 676비트 레지스터와 그대로 대응된다.

### Python 조작 인터페이스 (스케치)

실제 조작 순서(메뉴 작성 → 배선 → 구동 → 정지 확인 → 검증)를 그대로 따르게 한다. 세부 이름은 구현 때 확정한다.

```python
from christopher import Menu, Bombe

menu  = Menu.from_crib(ciphertext, crib="WETTERVORHERSAGE")   # 메뉴 작성
bombe = Bombe(model="british-3rotor")                         # 기계 선택
bombe.plug_up(menu)                                           # 메뉴대로 배선
for stop in bombe.run(wheel_orders="army"):                   # 구동
    result = stop.check()                                     # 체킹 머신
    if result.consistent:
        print(result.settings, result.decrypt(ciphertext))
```

### Phase 2 — RTL

- 언어: SystemVerilog. 스크램블러는 드럼 순열의 조합 논리(ROM 조회)로 구성.
- 핵심 설계 쟁점: 실제 봄베의 배선망은 전기적으로 즉시 수렴하지만, 이를 그대로 조합 논리로 옮기면 조합 루프가 생긴다. 676비트 레지스터를 클럭마다 전파시켜 고정점에 도달하는 동기식 구조로 설계한다.
- 검증: Rust 코어가 내보낸 벡터와 비교 (cocotb로 Python에서 구동하는 방식을 우선 검토).
- 착수 전 결정: 시뮬레이터(현재 이 PC에는 Verilog 도구가 없음), FPGA 보드, 병렬 인스턴스 수.

완료 기준: Phase 1.7의 벡터 전체에서 RTL 결과가 Rust 코어와 일치하고, FPGA에서 3로터 탐색이 동작한다.

  3대는 LUT 약 93%로 배선이 현실적이지 않아 **Nexys Video는 엔진 2대로 확정**. 실제 보드 동작 시험은 보드 확보 후 (두 보드 모두 구매 후보이며 아직 없음).
- PYNQ(7Z020, LUT 5.3만): 엔진 1대 예상. 설치된 Vivado에 Zynq-7000 디바이스 지원이 없어 빌드 대기.
- **문서화 요구 (사용자 지시 2026-11-14)**: FPGA(하드웨어 설계)를 모르는 사람이 따라올 수 있는 **코드 해설** — 각 모듈의 코드가 무엇을 하는지와 그 원리를 단계별로 설명한다. 사용법 안내가 아니라 "이 코드가 왜 이렇게 생겼고 어떻게 동작하는가"가 중심. 대상: `scrambler`/`bombe_core`/`bombe_sweep`(기준 RTL), `bombe_engine`(내부 순열·순열 표 파이프라인, 분산 RAM, 케이블 단위 전파, 고정점 판정), `bombe_array`, `uart_bridge`, `axil_bridge`, 그리고 같은 수준으로 Rust 코어(`enigma`/`menu`/`bombe`/`check`/`search`). 각 단계에서 실제 봄베의 어느 부분에 대응하는지, 소프트웨어와 하드웨어 사고방식이 어떻게 다른지(클럭, 레지스터, 조합논리, 파이프라인, 왜 첫 FPGA 구현이 LUT 40만 개가 됐는지 같은 실패 사례 포함)를 그림과 함께 설명한다. LaTeX 최종 보고서(Phase 5)의 본문·부록으로 들어간다.
  코드 해설 앞에 **FPGA 설계의 기본 사고방식**을 먼저 다룬다: 프로그램(순서대로 실행되는 명령)이 아니라 회로를 기술한다는 것(HDL), 모든 것이 동시에 동작한다는 것, 동기식 설계(클럭과 레지스터, 조합논리 사이의 한 클럭), 자원(LUT·FF·블록/분산 RAM·DSP)과 시간(클럭 수·클럭 주파수)의 교환, 파이프라인, 합성·배치·배선과 타이밍 클로저, 시뮬레이션 기준 모델과 합성용 설계의 구분, 검증 우선(기준 모델·벡터 대조) 개발. 각 개념은 이 프로젝트 코드의 실제 예로 설명한다.
  설명 원칙 (사용자 지시): 개념마다 ① **왜 그렇게 되는지**(원리·메커니즘) ② 이 프로젝트 밖의 **일반적인 예**(카운터, LED 점멸, 덧셈기, FIFO, 신호 처리 필터 같은 교과서적 회로) ③ 이 프로젝트의 예, 순서로 쓴다. **그림을 적극적으로 쓴다** — 회로도·블록도·타이밍 다이어그램·파이프라인 도식·자원 비교 그래프를 TikZ(타이밍은 tikz-timing)로 직접 그린다. 모든 입문자용 설명은 `.tex`로 작성한다.
  만든 결과물(드럼 PCB, 메뉴 카드, 릴레이 회로, 기어 기구, FPGA 보드 구성 등)은 보고서에 **외형(렌더·외형도), 동작, 회로도**를 함께 싣는다 (사용자 지시 2026-11-15).
  보고서 본문도 같은 방식을 따른다: 그림 + "왜 그렇게 되는가". 단 이 프로젝트 밖의 일반 예(②)는 입문자용 가이드에만 넣고 보고서에는 넣지 않는다.

### Phase 3 — 실물 (투트랙: 기어식 + 릴레이식)

같은 봄베를 두 가지 방식으로 만든다. 둘 다 전기기계식이며(전기 회로 + 움직이는 기계 부품), 움직이는 부품이 회전 드럼이냐 릴레이 접점이냐가 다르다.

- **기어식 (G 트랙)**: 실제 영국 봄베의 방식. 드럼이 기어로 물리적으로 회전하고, 브러시가 접점판을 훑으며 드럼 내부 배선으로 전류가 흐른다.
- **릴레이식 (R 트랙)**: 회전 부품 없이 릴레이로 구성한다. 로터 위치는 릴레이 계수기가 세고, 위치에 따른 치환은 릴레이 접점망이 전환한다. 미 육군이 벨 연구소와 만든 봄베가 드럼 대신 릴레이를 쓴 선례다(세부는 7절 자료 조사에서 확인).

| 기능 | 기어식 | 릴레이식 |
|---|---|---|
| 위치 진행 | 모터 + 기어열, 단 사이 자리올림 | 릴레이 계수기 (26진 3자리) |
| 스크램블링 (로터 치환) | 회전 드럼의 브러시·접점판·내부 배선 | 릴레이 접점망 |
| 메뉴 배선·대각선 보드 | 공용 | 공용 |
| 정지 감지 | 공용 (릴레이) | 공용 (릴레이) |

두 방식 모두 각 위치에서 가설이 모순인지 판정하는 것은 배선을 흐르는 전류다. 방식의 차이는 "위치를 어떻게 진행시키고 치환을 어떻게 바꾸는가"에 있다.

**공통 구조.** 두 트랙의 스크램블러가 같은 인터페이스(26선 입력, 26선 출력, 위치 진행 신호)를 갖게 한다. 메뉴 배선, 대각선 보드, 정지 감지는 한 번만 만들어 함께 쓰고 스크램블러만 바꿔 끼운다. 이렇게 하면 중복 제작이 줄고, 같은 메뉴를 두 방식으로 돌려 결과를 직접 비교할 수 있다.

**규모.** 처음부터 전체 규모를 목표로 하지 않고 단계적으로 키운다.

- 기어식: 실제 3로터 봄베는 드럼 108개, 드럼당 브러시 104개(전체 약 1만 1천 개)다.
- 릴레이식: 접점 수가 설계의 핵심 쟁점이다. 위치마다 접점을 따로 두는 단순 구성은 스크램블러 1유닛에 접점 약 4천 개가 필요하다. 로터를 "고정 배선 + 앞뒤의 순환 시프트"로 나누고 시프트를 이진 단계(1·2·4·8·16칸)로 구성하면 약 1,500개 수준으로 줄어든다. 둘 다 개략 추정이며 설계 때 다시 계산한다.

| # | 단계 | 완료 기준 |
|---|---|---|
| 3.0 | 공통부: 스크램블러 인터페이스 정의, 정지 감지 회로, 메뉴 배선 패널 | 스크램블러 자리에 고정 배선을 물렸을 때 정지/통과가 예상대로 판정됨 |
| G.1 | 드럼 1개 + 접점판 시제품 | 회전 중 브러시 접촉이 안정적이고 26개 위치 모두에서 배선표대로 통전 |
| G.2 | 기어식 스크램블러 1유닛 (드럼 3개 + 기어 자리올림) | 17,576 위치를 빠짐없이 순회하고, 각 위치의 치환이 Rust 코어와 일치 |
| R.1 | 로터 1단 릴레이 접점망 | 26개 위치 모두에서 배선표대로 통전 |
| R.2 | 릴레이식 스크램블러 1유닛 (로터 3단 + 반사판 + 위치 계수기) | 17,576 위치를 빠짐없이 순회하고, 각 위치의 치환이 Rust 코어와 일치 |
| 3.3 | 트랙별 소규모 뱅크 | 같은 짧은 메뉴를 두 방식으로 돌려 같은 위치에서 정지 |
| 3.4 | 확장 | 규모는 3.3 결과를 보고 트랙별로 결정 |

3.0 이후 G 트랙과 R 트랙은 서로 의존하지 않으므로 병행할 수 있다.

Phase 2(RTL)와의 관계: 실물에서는 스크램블링을 드럼 또는 릴레이가 직접 하므로 FPGA가 논리를 대신하지 않는다. FPGA는 구동 제어와 기준 모델과의 결과 대조에 쓴다.

산출물: 기구 설계(CAD), 회로도, BOM, 제작 문서 → `hardware/common/`, `hardware/gear/`, `hardware/relay/`

**전시·실습 요구사항** (프로젝트 최종 목표에서 도출, 세부는 설계 단계에서 확정):

| 영역 | 요구 |
|---|---|
| 실습 흐름 | 관람객이 실제 운용자처럼 할 수 있어야 함: 준비된 암호문·크립 카드 고르기 → 메뉴 배선(패치 케이블) → 구동 → 정지 확인 → 체킹. 한 회 실습이 전시 동선에 맞는 시간 안에 끝나도록 축소 시나리오(짧은 메뉴, 제한된 위치 범위) 준비 |
| 안전 | 저전압(인체 안전 전압)만 노출, 회전부·기어에 투명 덮개와 인터록(덮개 열면 정지), 비상 정지 버튼, 끼임·화상·감전 위험 요소 제거 |
| 내구성·유지보수 | 장시간 반복 구동을 견디는 접점·브러시·기어 재질, 소모품(브러시·접점) 교체가 쉬운 구조, 자가 진단(기준 메뉴로 알려진 정지 위치 확인) 모드 |
| 가시성·설명 | 드럼 회전과 정지가 눈에 보이도록 배치, 전류가 흐르는 경로를 표시(램프 등), 설명 패널. 해설 내용은 보고서·입문자 해설과 같은 원리 설명을 재사용 |
| 복원·리셋 | 실습 후 초기 상태로 쉽게 되돌리기(배선 리셋, 드럼 원위치) |
| 전자 장치의 역할 | 소프트웨어는 세 기계의 기준 모델(결과 대조)·진단·관람객용 표시(해독 결과 화면). 기계식·릴레이식에서 해독 동작 자체는 기계가 한다 |
| 세 기계 비교 전시 | 같은 메뉴 카드를 기계식·릴레이식·FPGA에 걸어 같은 정지가 나오는 것을 보여 줌. 속도 비교 표시(기계식 위치당 수십 ms 수준 ↔ FPGA 위치당 수백 ns 수준, 실측으로 확정). FPGA는 움직이는 부품이 없으므로 내부 상태(676선, 드럼 위치, 정지)를 LED/화면으로 시각화하는 방안 필요 |

개념 설계 (2026-11-15): `hardware/common/design-brief.md`, `hardware/gear/concept.md`, `hardware/relay/concept.md`. 결정 13건은 권장안대로 진행 (12슬롯 설계·6유닛 먼저, 26글자, 실물은 3로터, 지름 약 96mm PCB 드럼 + 기계 쪽 스프링 접점, 스테퍼 구동·순수 기어 자리올림, 릴레이는 2진 5단 결합형 시프터 등). **예산과 전시 운영 방식은 고려하지 않는다** (사용자 지시: 예산 생각하지 말고 할 수 있는 대로).

세 트랙 모두 유지한다. 제작 순서는 Phase 3 단계표를 따른다(공통부 → G·R 병행). FPGA 전시물(Phase 2 결과물)은 시각화 장치를 추가해 완성한다.

### Phase 4 — 설명용 웹 시각화 (희망사항)

Rust 코어를 WASM으로 빌드하고 TypeScript로 드럼 회전·통전 전파·정지 과정을 시각화한다. 코어를 바인딩과 분리해 두는 이유가 여기에 있다.

### Phase 5 — 최종 보고서 (LaTeX)

프로젝트의 마지막 단계. Phase 4를 건너뛰더라도 보고서는 작성한다.

예상 구성:

1. 역사적 배경 — 에니그마, 블레츨리 파크, 튜링과 웰치먼
2. 에니그마의 원리와 약점 — 자기 자신으로 암호화되지 않는 성질, 플러그보드의 대칭성
3. 봄베의 원리 — 크립과 메뉴, 스크램블러, 대각선 보드, 정지 판정, 체킹
4. 소프트웨어 구현 — 코어 구조, 실제 기계와의 대응, Python 조작 예
5. RTL 구현 — 동기식 전파 구조, 검증, FPGA 결과
6. 실물 제작 — 기어식과 릴레이식, 두 방식의 비교(속도, 부품 수, 신뢰성)
7. 검증과 결과 — 실제 전문 해독, 정지 횟수 통계, 탐색 성능
8. 결론
- 부록: 배선표, 검증 벡터, 조작 절차

작성 원칙:

- **재료는 각 Phase에서 쌓는다.** 마지막에 몰아서 쓰지 않도록, Phase가 끝날 때마다 해당 장에 들어갈 결과와 그림을 남긴다. 출처는 `docs/reference/`에 기록하는 시점에 참고문헌 파일(`.bib`)에도 함께 넣는다.
- **수치와 그림은 스크립트에서 나온다.** 보고서의 표·그래프는 코어를 실행한 결과에서 생성하고, 배선표 부록은 `data/wirings/`에서 자동 생성해 손으로 옮겨 적다 생기는 오류를 막는다.
- **역사적 사실에는 출처를 단다.**

빌드 환경: 이 PC에 TeX Live 2025가 설치되어 있다(`xelatex`, `lualatex`, `latexmk`, `biber` 확인). 한국어 보고서를 기준으로 XeLaTeX 또는 LuaLaTeX + kotex, 참고문헌은 biblatex/biber, 빌드는 `latexmk`를 쓴다.

완료 기준: `latexmk` 한 번으로 PDF가 빌드되고, 모든 수치·그림을 스크립트로 다시 만들 수 있다.

| 릴레이식 구성 | 릴레이 종류(극 수, 전압), 접점망 구성 방식(단순 구성 또는 이진 시프트) | R.1 전 |
| 보고서 언어·양식 | 한국어로 가정했다. 영어로 쓰거나 특정 양식(학위논문, 학회 템플릿 등)이 있으면 변경 | Phase 5 전 (빠를수록 좋음) |

## 7. 확인이 필요한 사항 (Phase 0 자료 조사)

아래는 구현 정확성에 직접 영향을 주므로 기억에 의존하지 않고 1차 자료로 확인한 뒤 `docs/reference/`에 출처와 함께 기록한다.

- 봄베 드럼 배선과 에니그마 로터 배선의 관계 (드럼별 글자 오프셋)
- 드럼 3단의 구동 순서와 각 단이 에니그마의 어느 로터에 대응하는지
- 드럼 구동 기구: 기어열 구성, 단 사이 자리올림 방식, 회전 속도
- 드럼과 접점판의 물리 구조: 브러시 배열(동심원 4줄), 치수, 접점 재질
- 미 육군 릴레이식 봄베의 구조: 로터 치환과 위치 진행을 릴레이로 어떻게 구현했는지
- 테스트 레지스터의 정확한 정지 조건과 정지 시 표시되는 정보
- 체킹 머신의 실제 절차
- 미 해군 4로터 봄베의 유닛 수·구조, 영국식 4로터 봄베 변형들의 차이
- 메뉴 품질과 예상 거짓 정지 수의 관계 (튜링의 추정표)

computer_christopher/
├── README.md
├── docs/
│   ├── PLAN.md              이 문서

├── data/
│   ├── wirings/             로터·반사판·드럼 배선표 (Rust·RTL 공용 원본)

│   └── christopher-py/      PyO3 바인딩
├── python/
│   └── christopher/         Python 조작 API 패키지
├── tests/                   Python 수준 통합 시험
├── notebooks/               조작 예제·시연
├── rtl/                     Phase 2
├── hardware/                Phase 3
│   ├── common/              공통부: 스크램블러 인터페이스, 정지 감지, 메뉴 배선
