## 1. 왜 바꾸는가

지금 해설서는 FPGA 개념(1부, `01`–`06`)으로 시작하고 릴레이(5부)와 기어(6부)는 뒤에 붙어 있다. 그 결과 설명의 방향이 거꾸로다.

- 릴레이 장이 FPGA 장을 빌려 설명한다. `40-relay-logic.tex` 87·140·597·674행("hdl장의 게이트는…", "sync장의 '클럭 에지에서만 바뀐다'는 성질을 이렇게 만든다"), `41-relay-timing.tex` 3행("sync장의 동기식 회로에는 시간 규칙이 하나뿐이었다").
- 눈에 보이는 것(접점이 닫히고 전류가 퍼짐)을 눈에 안 보이는 것(LUT·플립플롭)으로 설명하고 있다. 반대여야 한다.
- 전시가 보여 주려는 순서(기계 → 전기기계 → 전자, 컴퓨터 발전사)와 문서 순서가 다르다.

## 2. 이야기의 줄기

봄베의 계산은 두 가지 일이다.

1. **연결을 만든다.** 로터 위치마다 676가닥 선 사이에 어떤 연결이 생기는가(스크램블러가 바꾸는 연결 + 대각선 보드의 고정 연결).
2. **이어진 선을 찾는다.** 전압을 건 선에서 닿을 수 있는 선을 모두 찾는다(그래프의 도달 가능성).

세 기계(와 기준 모델)는 이 두 일을 서로 다른 수단으로 한다. 이 표가 문서 전체의 지도다.

| | 연결을 만드는 법 | 이어진 선을 찾는 법 |
|---|---|---|
| 기어식 | 드럼이 실제로 돌아 배선이 바뀜 | 전류가 한꺼번에 퍼짐 — 탐색을 물리가 공짜로 함 |
| 릴레이식 | 회전 없이 접점(이진 시프터)이 배선을 바꿈 | 전류가 퍼짐 |
| FPGA | 접점 대신 논리(표·선택 회로)가 배선을 정함 | 전류가 없음 — 클럭마다 한 단계씩 퍼뜨리고 더 안 바뀔 때까지(고정점) 되풀이 |
| Rust 기준 모델 | 표를 찾음 | 스택으로 하나씩 방문(`propagate`) |

핵심 문장: **FPGA가 어려운 이유는 물리가 공짜로 하던 탐색을 회로로 직접 지어야 하기 때문이다.** LUT 40만 개 사례(`06-lesson`)의 원인이 바로 전파 논리 두 줄이었으므로, 그 장은 이 줄기의 결말이 된다. 조합 고리를 레지스터로 끊는 결정(`21-rtl-core` 첫 절)도 같은 이야기다.

## 3. 걸리는 점: 기어식도 릴레이를 쓴다

기어식을 릴레이식보다 앞에 두려면 하나를 풀어야 한다. 기어식은 연결을 드럼으로 만들지만, **판정(테스트 레지스터)은 릴레이로 한다.** 테스트 레지스터와 시간 원칙(`41`의 앞 세 절)은 두 기계의 공통부다. 그리고 기어식 시간 절(`sec:t-gear`)은 지금 `41` 안에 있고 `sec:t-bounds`("느려지면 늘 안전하다")에 기댄다.

**해결:** 릴레이를 *부품*과 *기계*로 나눈다.
- 부품으로서의 릴레이(코일과 접점, 접점 논리, 자기 유지, 먼저 끊고 나중에 잇기, 역기전력 다이오드)는 다이오드·트랜지스터처럼 기초 부품으로 앞에 둔다.
- 기계로서의 릴레이식(접점 나무, 이진 시프터, 계수기, 순서기)은 기어식 뒤에 둔다.

## 5. 1부 새 장의 내용

코드 없이 그림과 예로만 쓴다(코드는 2부부터).

**A장 "연결이란 무엇인가"**
- 에니그마·크립·메뉴 최소 설명 (현 `sec:bombe-one-page`에서 옮김, 그림 `fig:g-menu`, `fig:g-bombe-front` 포함).
- 전기 최소: "전류는 끊기지 않은 길로만 흐른다"(`39` 전체는 3부에서).
- 선과 연결: 676가닥 = 26글자 케이블 × 26선, 가설 "E의 짝이 V".
- 연결 두 종류: 위치마다 바뀌는 연결(스크램블러), 늘 같은 연결(대각선 보드). 메뉴 하나로 실제 연결 몇 개를 손으로 그려 본다.
- 연결은 그래프다: 점 = 선, 간선 = 연결.

**B장 "이어진 선을 찾는 법"**
- 물리로 찾기: 전압을 걸면 이어진 선이 한꺼번에 통전. 병렬이고 시간이 거의 들지 않는다.
- 계산으로 찾기: 한 단계씩 퍼뜨리기(너비 우선/스택), 더 안 바뀔 때까지 되풀이(고정점), 합집합–찾기. 같은 메뉴 예로 단계별 그림. `43`의 `sec:v-uf`·`sec:v-fixpoint`, `12`의 `sec:propagate`가 나중에 이 개념을 다시 쓴다는 예고.
- 결과 읽기: 테스트 레지스터 26선이 전부 통전 = 모순 → 정지 아님.
- 2절의 표(세 기계 × 두 일)를 그림으로. 이후 각 부가 이 표의 한 행이라는 지도.

## 6. 6부 개념 장 다시 쓰기 (`01`–`06`)

기존의 세 단계(왜 그런가 / 일반적인 예 / 이 프로젝트에서) 앞에 **"릴레이에서는"** 단계를 하나 두고, 3·5부의 회로에서 출발해 FPGA로 옮긴다. `\steptag` 색을 하나 더 정의한다.

| 장 | 릴레이에서 출발 | FPGA로 |
|---|---|---|
| C (새) 대응표 | 릴레이식·기어식 부품 목록 | `30` 끝의 대응표(감지 릴레이 26개 ↔ `test_q != FULL`, 고정 배선 대각선 보드 등)를 넓혀 6부 첫머리 지도로 |
| `01` 회로를 기술한다 | 배선도, 접점 직렬·병렬, 접점 나무를 26번 복사, 모든 릴레이가 동시에 움직임 | HDL은 배선도를 글로 적은 것; `&`·`\|`, 반복문 = 공간, 동시성 |
| `02` 동기식 설계 | 자기 유지, `CK` 펄스, 계수기, 555+링 계수기 순서기 | 플립플롭, 클럭, `<=`, 상태 기계 |
| `03` 자원 | 릴레이 수(6유닛 3,455), 기판 장수; 이진 시프터 = 회전의 선택 회로 | LUT·FF·분산 RAM; `sec:mux-cost` |
| `04` 시간 | 최악 릴레이 시간에서 L1–L9 성립(`sec:t-bounds`), 63 ms 주기 | 최악 경로 지연, 타이밍 클로저, 파이프라인, 50 MHz |
| `05` 검증 | 릴레이 보드도 넷리스트 시뮬레이션으로 기준 모델과 대조(7부 `43` 예고) | 내용 대부분 유지 |
| `06` LUT 40만 개 | 1부 B장: 전류가 없으니 퍼뜨림을 회로로 지어야 함 | 첫 단락을 이 줄기의 결말로 다시 틀 잡기, 본문 유지 |

`20`–`22`·`30`은 다시 쓰지 않는다. 이미 있는 대응 문장(`22` 4·122·176행, `30` 458·583·951행)의 참조를 4·5부로 잇고, `21` 첫 절(고리를 레지스터로 끊는다)에 1부 B장과 테스트 레지스터(`sec:t-register`) 연결 한 단락을 더한다.
